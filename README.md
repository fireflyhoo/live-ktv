# 弹幕蹦迪舞台 · Danmaku Disco

直播间的每条评论，都会在舞台上变成一个小人。小人是像素风的，头顶顶着评论人的昵称，在舞池里踩着 128 BPM 的节拍蹦迪；如果评论里带表情包，小人头顶会弹出那个表情。

支持 **腾讯视频号 / 抖音直播 / B 站直播**。

**画面和控制台是两个独立页面**，这是刻意分开的：

| 页面 | 地址 | 用途 |
|---|---|---|
| **舞台** | `http://127.0.0.1:8787/` | 纯画面，没有任何 UI。给 OBS 采集、给投屏用 |
| **控制台** | `http://127.0.0.1:8787/console.html` | 你操作的地方：调模式、调节奏、投喂弹幕、看统计，还自带实时预览 |

两个页面之间走同源广播（BroadcastChannel），控制台改什么，舞台**即时**生效，不用刷新。服务还挂了一条 WebSocket 兜底，跨设备也能控。

---

## 一、跑起来

```bash
cd live-ktv
node server/bridge.js
```

然后打开 **<http://127.0.0.1:8787/console.html>**（先开这个）。

服务同时做三件事：托管页面、接收 HTTP 弹幕、WebSocket 广播。零依赖，只用 Node 内置模块。

进来默认跑的是**弹幕模拟器**，你会看到小人不断冒出来蹦迪，方便先看效果。想接真实弹幕看第四节。

### 舞台规格

控制台第一项就是「舞台规格」，两种取景框：

- **PC 横版 16:9** — 场景分辨率 640×360，适合 OBS 采集、投大屏
- **手机竖版 9:16** — 场景分辨率 216×384，适合手机竖屏直播 / 短视频

切换时布景（LED 墙、桁架灯、光束、音箱、地板网格、人群）会整套重排适配新比例；已经在场上的小人按比例挪位置，不会被清掉。

### OBS 用法

1. 来源 → 添加 **浏览器源**
2. URL 填 `http://127.0.0.1:8787/?mode=transparent&panel=0`（控制台底部可以直接复制这行；竖屏的话会带上 `&ratio=vertical`）
3. 横屏填 1920×1080，竖屏填 1080×1920，勾选「控制音频时刷新浏览器源」
4. 控制台上把**弹幕来源**切到「外部接入」

这样采集到的画面是纯小人和名牌，直接压在你的直播画面上。舞台页本身不带任何按钮和面板，所以不用再操心把 UI 抠掉。

### 舞台页的快捷键

| 键 | 作用 |
|---|---|
| `H` | 关掉「控制台在哪」的提示条 |
| `C` | 清场 |
| `B` | 随机来一波弹幕 |
| `F` | 全屏 |

### URL 参数

方便在 OBS 或不同场景里直接配好，不用每次手动调：

| 参数 | 说明 | 示例 |
|---|---|---|
| `mode` | `stage` / `transparent` | `?mode=transparent` |
| `ratio` | `wide`（16:9）/ `vertical`（9:16） | `&ratio=vertical` |
| `panel` | `0` 隐藏所有提示性 UI | `&panel=0` |
| `max` | 同屏小人上限，5–80 | `&max=20` |
| `rate` | 模拟器节奏，条/秒 | `&rate=1.2` |
| `src` | `sim` / `live` | `&src=live` |
| `preview` | `1` = 这是控制台里的预览实例，不参与配置回传 | `?preview=1` |

控制台上的设置会存进 localStorage，下次打开自动恢复；URL 参数优先级更高。**舞台是配置的主人** —— 控制台启动时先向舞台问一句当前状态，以舞台为准。

## 二、小人是怎么来的

一条弹幕进来，处理流程是：

```
弹幕 → 找同昵称的老小人？→ 有：换表情、续命、重新欢呼
                        → 没有：在舞池里找个空位，生成新小人
```

几个细节：

- **同一个人长相一致**。每个小人的发色、衣服、裤子、舞步、站位深度由一个以昵称为种子的伪随机数决定。老观众回来还是那个小人。
- **舞步有 6 种**：蹦跳、举手跳、摇摆、机械舞、转圈、踏步。其中 72% 的人踩在同一个拍点上，剩下的错开半小节，这样人群是「整体跳动 + 少量错落」，不会像一群各自抽搐的虫子。
- **站位是 2.5D 的**。小人随机落在后排到前排之间，越靠前越大。牌子也跟着做透视缩放，前大后小。
- **名字会互相让**。人多的时候牌子会往上叠，前排的优先保留原位；叠得太高的牌子会淡出，宁缺毋滥，不会糊成一团。被抬高的牌子有一条细引线连回小人头顶。
- **生命周期**：默认停留 22–32 秒后退场。同一个昵称再次发言会续命。超过同屏上限时，**随机请走几位**（不是按年龄排队），让舞池一直有流动感。一次推几十条弹幕也不会挤爆 —— 舞台有个上台队列，每 70ms 放 2 个人，用定时器而非渲染帧驱动（OBS 后台标签页里 rAF 会被节流）。
- **保底 10 人**：台上不足 10 个人时谁都不许自然退场，寿命到了只会往后顺延；等人数够了，再各自错开 6–16 秒陆续离开，不会集体消失。想改这个数字就调 `js/app.js` 里的 `MIN_LIVE`（同屏上限比 10 还小时以 `max` 为准）。

## 三、给 Claude 看的：接入真实弹幕

不管是哪个平台，最后只要把弹幕变成这个结构送进来就行：

```json
{
  "user": "昵称",
  "text": "评论内容",
  "emote": "😍",
  "emoteUrl": "",
  "platform": "bili | douyin | wx",
  "isVip": false
}
```

`emote` 是 emoji，`emoteUrl` 是图片表情包地址（两个都有时优先显示图片，B 站的付费表情就是这个路子）。`platform` 决定名牌左侧小圆点的颜色。

### 方式 1：HTTP POST

```bash
curl -X POST http://127.0.0.1:8787/danmaku \
  -H 'Content-Type: application/json' \
  -d '{"user":"小明","text":"主播好帅 😍","platform":"douyin"}'
```

任何语言、任何平台的抓取脚本都能这么推。支持单条或数组。

### 方式 2：WebSocket

```js
const ws = new WebSocket('ws://127.0.0.1:8787');
ws.onopen = () => ws.send(JSON.stringify({ user: '小明', text: '来啦', platform: 'wx' }));
```

页面端的「外部接入」模式就是连这个。断开会自动重连。

### 方式 3：postMessage

```js
window.postMessage({ type: 'danmaku', user: '小明', text: '来啦' }, '*');
```

同一个页面里塞消息用这个最省事。

### 方式 4：视频号直播整包推送（抓取脚本推荐用这个）

抓取脚本一般是**定时把当前直播间快照整包推过来**，格式长这样：

```json
{
  "type": "video_channel_live",
  "capturedAt": "2026-11-02T13:50:46.392Z",
  "comments": [
    { "type": "主播", "username": "古望舒", "content": "测试", "desc": "", "capturedAt": 1793627446392 }
  ],
  "viewers": [
    { "rank": 1, "name": "梁真秀", "gender": "", "value": "0", "level": "", "capturedAt": 1793627446392 }
  ]
}
```

不用自己拆包，整包 POST 进来：

```bash
curl -X POST http://127.0.0.1:8787/video-channel-live \
  -H 'Content-Type: application/json' \
  -d '{"type":"video_channel_live","comments":[{"username":"古望舒","content":"测试"}],"viewers":[]}'
```

也可以用浏览器 / 油猴脚本跨域推：

```js
fetch('http://127.0.0.1:8787/video-channel-live', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(snapshot)
});
```

服务端会做这几件事：

| 处理 | 说明 |
|---|---|
| 拆包 | `comments` 逐条转成 `{user: username, text: content, platform: 'wx'}`；`type:"主播"` 的发言给 VIP 名牌 |
| 观众上场 | `viewers` 也变成小人（见下节），带 `quiet` 标记：只站着 / 续命，不弹气泡、不飘屏 |
| 跨批次去重 | `username + content + capturedAt` 做幂等指纹，10 分钟内重复推同一份老快照不会再上台；另有 20 秒 `username + content` 短窗口兜底，防止脚本每次重写 `capturedAt` |
| 同批同名去重 | 一批里同名只留最新一条，不会一次刷出一排同名人 |
| 舞台同名合并 | 舞台上同一个昵称永远只有一个小人，再推送只是换内容 / 续命 / 重新欢呼；人数接近上限时随机请走几位，但台下不足 10 人时一个都不走 |

`viewers` 是观众榜，**默认也会上台**：榜单里的人本来就是直播间里的观众，没发言也该站在舞池里。

- 默认取 rank 前 20 位（`?maxViewers=50` 调数量，`?maxViewers=0` 不限）
- 他们**不弹评论气泡、不进底部飘屏**，只是站着跳舞；榜单前三名给 VIP 名牌
- 同一位观众 12 秒内只会被推一次（续命），所以反复推快照不会刷屏，人也不会掉
- 同一次推送里既发言又在榜上的人，只算一个，按发言处理（有气泡、有内容）
- 不想要他们上台就加 `?includeViewers=0`

**跨域**：接口返回 `Access-Control-Allow-Origin: *`，自动回显预检请求里声明的自定义头，正确处理 `OPTIONS` 预检，并支持 Chrome 私有网络访问的 `Access-Control-Allow-Private-Network`。从任意来源的页面直接 fetch 都行。

返回体方便排查：

```json
{ "ok": true, "accepted": 6, "duplicates": 1, "comments": 5, "viewers": 4, "viewersOnStage": 3 }
```

整包推到旧的 `/danmaku` 地址也能识别（只要带 `comments` 数组就走同一套适配）。

### 终端里能直接看到推了什么

启动服务的那个终端会逐条打印每次推送的内容，不用去翻浏览器：

```text
◀ video_channel_live 推送  22:32:50  from 本机
  type=video_channel_live  capturedAt=2026-11-02T13:50:46.392Z
  评论  5 条   观众  4 位   原始 JSON 918 B
  主播 古望舒        21:50:46 测试                           · 同批重名
  观众 梁真秀        21:50:46 来啦 😍 主播今天唱什么          ✓ 上台
  观众 阿柯          21:50:46 主播好帅                       ✓ 上台
  观众 一个名字特别特…21:50:46 这是一条很长很长的评论内容用来… ✓ 上台
  观众榜 #1 梁真秀  #2 阿柯(128)+  #3 小满(66)+  #4 路人甲+   （+ 表示已上台 / 续命）
  → 上台 6   其中观众榜 3   跳过 1
```

每条评论后面标着它的去向：`✓ 上台` / `· 同批重名` / `· 已推过`。观众榜那一行末尾带 `+` 的是这一轮真的上台 / 续命了的（12 秒节流，所以不是每次都有）。JSON 解析失败或缺 `comments` 也会打印原文前 120 字并标红，抓取脚本字段写错时一眼能看出来。

### 字段清洗说明

拿到数据后，统一的清洗逻辑在 `js/danmaku.js` 的 `normalize()`：兼容 `nickname`/`username`/`uname`/`name`、`content`/`msg`/`comment`/`desc`、`emoticon`/`face` 等别名，也会自动从纯文本里抠出第一个 emoji 当头顶表情包。所以抓取脚本不用刻意对齐字段名。

另外，外部推送的 WebSocket 是**常连**的：不管控制台上「弹幕来源」切到模拟器还是外部接入，推过来的弹幕都会进舞台。想只看真实弹幕，把来源切到「外部接入」关掉模拟器即可。

## 四、三个平台怎么接

这部分说实话：**B 站最好接，抖音次之，视频号最麻烦。**

| 平台 | 可行路径 | 说明 |
|---|---|---|
| **B 站直播** | 服务端直连弹幕 WebSocket（社区成熟方案），或走官方开放平台 | 弹幕 protocol 公开度高、稳定。拿到后 POST 到本地服务即可 |
| **抖音直播** | ① 官方开放平台的互动能力（需资质）② 网页直播间 DOM 抓取转发 | 直播间网页版的弹幕节点是可读的，自用足够；逆向 WebSocket 签名方案随时可能失效，不建议依赖 |
| **腾讯视频号** | 网页端直播间 DOM 抓取转发 | **没有任何公开的弹幕接口**，只能从网页直播间读。抓到的整包快照直接 POST 到 `/video-channel-live`，服务端负责拆包和去重 |

无论走哪条路，**最后一公里都一样**：单条弹幕 POST 到 `/danmaku`，整包快照 POST 到 `/video-channel-live`。平台差异被封死在这一步之前。

### 浏览器端抓取脚本（抖音 / 视频号）

`tools/grab.user.js` 是一个油猴脚本骨架，在网页直播间里监听弹幕节点，转发到本地服务。因为平台前端结构会改，**选择器需要根据你看到的实际页面微调**（脚本里集中在一个 `SELECTORS` 对象里，改那里就行）。

用法：

1. 浏览器装 Tampermonkey
2. 把 `tools/grab.user.js` 内容粘进去，按注释改 `SELECTORS` 和平台
3. 打开自己的直播间
4. 控制台上把弹幕来源切到「外部接入」

> 合规提醒：这套东西请只用在**你自己的直播间**。批量抓取他人直播间数据可能违反平台协议，也可能涉及个人信息合规问题，别踩。

## 五、文件结构

```
live-ktv/
├── index.html              舞台页：纯画面，无 UI，给 OBS 采集
├── console.html            控制台页：预览 + 所有控制项
├── css/
│   ├── stage.css           舞台样式（含两种显示模式的切换规则）
│   └── console.css         控制台布局（左预览 / 右面板）
├── js/
│   ├── palette.js          像素调色板、节拍常量、缓动、种子随机
│   ├── dancer.js           像素小人：6 套舞步、23px 高的方块人
│   ├── stage.js            舞池场景：LED 墙/光束/迪斯科球/地板/音箱/人群剪影
│   ├── overlay.js          高清 DOM 层：名牌、表情包、评论气泡、标签避让、飘屏
│   ├── danmaku.js          弹幕接入层：模拟器 / WS / postMessage / 数据清洗
│   ├── link.js             舞台与控制台之间的通道（BroadcastChannel + WS）
│   ├── app.js              舞台主控：缩放布局、主循环、生成小人、接收指令
│   └── console.js          控制台主控：下发指令、显示统计
├── server/bridge.js        零依赖中转服务：静态托管 + HTTP + WebSocket
└── tools/grab.user.js      浏览器端弹幕抓取脚本（抖音/视频号）
```

### 想改哪里

| 想改的东西 | 去哪改 |
|---|---|
| 小人的样子（配色、身高） | `js/palette.js` 色板 + `js/dancer.js` 的 `draw()` |
| 舞步 | `js/dancer.js` 的 `pose()`，一个 switch，加个 case 就行 |
| 跳舞快慢 | `js/palette.js` 的 `BPM` |
| 牌子 / 表情包样式 | `css/stage.css` 的 `.dancer-*` |
| 小人停留多久 | `js/dancer.js` 构造里的 `this.life` |
| 模拟器的话术 | `js/danmaku.js` 顶部的 `NICKS` / `LINES` / `EMOTES` |
| 背景舞厅 | `js/stage.js` |

渲染上刻意做的一个取舍：**小人现场 640×360 的低分辨率 canvas 上，整体放大到屏幕并保持硬边**；中文昵称和表情包则是高清的 DOM 层。这样既有像素颗粒感，文字又不会糊。

## 六、已知限制

- 模拟器只是给你看效果的，**没有接任何真实平台**，切到「外部接入」且没有服务时左上角会显示「未连接」。
- 单页单实例，别开太多标签页同时渲染，帧率会掉。
- 同屏 80 个是硬上限，再多人眼也看不过来，机器也累。
